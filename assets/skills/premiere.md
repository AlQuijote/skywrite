# Premiere Pro interchange

1. Inspect original media with `skywrite inspect INPUT` and prepare a version 1 edit from `skywrite schema`. Put continuous dialogue on the bottom video track or an audio track and B-roll/titles on upper video tracks.
2. Validate with `skywrite edit validate edit.json`.
3. Export: `skywrite edit export edit.json --to premiere --output edit.xml`. This writes Final Cut Pro 7 XML (xmeml v5), which Premiere imports with File → Import.
4. Read the JSON warnings. Subframe word-precise in points are rounded to whole frames; this includes recorder audio placed by `sync apply`, whose sub-frame `source_in` moves by up to half a frame (about 21 ms at 24 fps), so check that sync after import; LUTs and the master limiter are not representable, so apply them in Premiere (Lumetri → Input LUT; a limiter on the mix bus) to match the rendered MP4.
5. Media paths: by default the XML references this machine's absolute `file://localhost/...` paths and embeds no files. When the export is made somewhere else (a cloud machine) than where Premiere runs, add `--media-root FOLDER` with the editor's absolute folder (`/Users/NAME/Projects/film` or `D:\Projects\film`). Every source is then written beneath that folder with its path relative to `media_base` (reported in the result: the folder holding the edit and all its media). Tell the user to copy `media_base`'s contents to that folder, keeping subfolders, so Premiere links on open. Keep media file names unique; a warning lists any shared names, because after one manual relink Premiere's Locate finds the rest by name.
6. Audio is written the way Premiere itself exports it: each stereo layer is a pair of exploded tracks (one clipitem per channel, linked with its video) and mono sources go to mono tracks, so in Premiere a stereo recorder shows as one stereo clip on A1, not two tracks. After import, check that every audio track has its clips, plus layers, linked audio, speed (Time Remap), opacity fades, audio level keyframes, and total duration against a Skywrite render of the same edit. Video clips carry a Basic Motion Scale that fits them in the sequence like the render for square-pixel sources (rotated phone footage by its upright size; anamorphic or DV media frames differently, because Premiere applies its pixel aspect ratio); check framing after import.
7. Captions: add `{"from_transcripts": ["words.json"], "language": "eng"}` to the edit's `captions`. Each transcript requires `usage.source_sha256`, 64 hex digits (case-insensitive) matching the source media content SHA-256; byte-identical copies are accepted. Missing, invalid or mismatched fingerprints fail; re-run `skywrite transcribe` on the media, or point the transcript/edit at the media it was made from. The export writes `edit.eng.srt` beside `edit.xml`; tell the user to import both files together in Premiere and drag the caption item onto the sequence at 00:00:00:00. Captions stay editable as text. Premiere XML itself cannot carry captions.
8. Bring an editor's changes back with `skywrite edit import edit.xml -o edit.json` (Premiere: File > Export > Final Cut Pro XML). `.prproj` import is experimental.
9. Record the result with `skywrite nit`, including the Premiere version, import errors, and any timing or level differences. Cite the exporter source (`src/export/xmeml.rs` at https://github.com/FlyCockpit/skywrite) when describing a mismatch.

Linux-side validation (an independent OpenTimelineIO reader) checks structure and timing, not Premiere's own import behavior.
